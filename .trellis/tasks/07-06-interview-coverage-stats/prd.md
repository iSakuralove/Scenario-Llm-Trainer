# 面试覆盖率统计 PRD

## 目标

补齐面试舱剩余硬缺口“面试覆盖率统计”，让用户在现有面试启动台里直接看到：

- 当前开放训练轨道里，自己已经覆盖了多少
- 主要覆盖了哪些领域、难度和知识点
- 还有哪些开放轨道尚未训练

本任务只增强现有 `GET /api/v1/interviews/launchpad` 聚合接口和面试舱页面展示，不新建独立 Mentor 页面，不引入新的后台治理流程，也不额外新增独立接口。

## 已确认事实

- 当前面试舱已经接入 `launchpad` 聚合接口，包含：
  - `summary`
  - `recommended_tracks`
  - `recent_sessions`
  - `coverage`
- 当前“覆盖摘要”只反映题库开放范围，不反映用户自己的历史训练覆盖率。
- 当前面试报告已经能生成 `retrieval_summary.coverage`，可复用为用户历史知识点覆盖来源。

## 需求

1. 覆盖率统计口径
   - 以当前 `launchpad.open_tracks` 作为“可训练总范围”。
   - 以用户已完成的面试会话作为“已覆盖范围”。
   - 覆盖率至少输出：
     - 当前开放轨道总数
     - 已覆盖开放轨道数
     - 覆盖百分比
     - 已完成面试场次

2. 覆盖维度
   - 需要输出用户已覆盖的领域、难度。
   - 需要输出基于历史报告聚合得到的知识点数量和高频知识点摘要。
   - 需要输出尚未覆盖的开放轨道标识，供前端做“待补方向”展示。

3. 接口边界
   - 不新建独立接口，复用 `GET /api/v1/interviews/launchpad`。
   - 返回字段必须是聚合后的用户安全视图，不能暴露原始检索日志、原子正文、评分内部细节。

4. 前端展示
   - 面试舱页面新增“训练覆盖率”信息块。
   - 至少展示：
     - 覆盖百分比
     - 已覆盖/总开放轨道
     - 已覆盖领域
     - 高频知识点
     - 待补训练方向
   - 空状态下要给出清晰提示，不因无历史训练而报错。

## 验收标准

- `GET /api/v1/interviews/launchpad` 返回新的 `coverage_stats` 聚合字段。
- 有历史已完成面试时，覆盖率统计能正确计算已覆盖轨道数和覆盖百分比。
- 无历史已完成面试时，覆盖率字段仍存在，且前端显示空状态提示。
- 面试舱页面能展示覆盖率统计，不影响现有启动、推荐、历史入口。

## 不做

- 不做独立 AI Mentor 页面。
- 不做新的 `/users/me/knowledge-coverage` 独立接口。
- 不做基于 LLM 的覆盖诊断文案生成。
- 不做管理员覆盖率总览大盘。
