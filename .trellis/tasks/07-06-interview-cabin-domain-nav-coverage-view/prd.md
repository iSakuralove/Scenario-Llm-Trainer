# 面试舱领域导航与覆盖查看交互 PRD

## 目标

把面试舱启动台里两个还没落地的前端交互补齐：

- `Domain` 作为主导航过滤入口，而不是只选中第一个轨道
- 推荐训练卡提供次按钮 `查看覆盖`

本任务只改现有 `InterviewsPage` 交互和 smoke 验证，不新增接口、不改后端聚合结构。

## 已确认事实

- 当前开放轨道已经支持 `category / difficulty / question_role / tags` 轻量筛选。
- 当前 `Domain chip` 点击后只会选中第一个轨道，不会真正驱动筛选状态。
- 当前推荐卡只有整卡点击选中行为，没有“查看覆盖”次按钮。
- 前端设计文档明确要求：
  - `Domain` 是页面导航主轴
  - 推荐卡应有主按钮“开始训练”和次按钮“查看覆盖”

## 需求

1. Domain 主导航
   - 点击某个 `Domain chip` 后，必须驱动当前开放轨道筛选。
   - 当前实现可复用已有 `category` 过滤状态，不必新造第二套筛选模型。
   - 再次点击当前激活的 `Domain chip` 时，允许取消过滤回到“全部”。
   - 当前激活的 `Domain chip` 必须有可见态。

2. 推荐卡查看覆盖
   - 推荐卡增加 `查看覆盖` 次按钮。
   - 点击后至少要：
     - 把当前过滤切到该推荐轨道所属领域
     - 选中该轨道
     - 跳转/滚动到覆盖或轨道相关区域，形成明确反馈
   - 不要求新增独立覆盖页。

3. 兼容性
   - 不影响当前整卡点击选中推荐轨道的能力。
   - 不影响已有筛选条和开始面试流程。
   - 不影响移动端与 smoke 路径。

## 验收标准

- 点击任一 `Domain chip` 后，分类筛选值变为对应领域，开放轨道列表按领域过滤。
- 再次点击当前激活领域后，分类筛选可恢复为空。
- 推荐卡存在 `查看覆盖` 次按钮。
- 点击 `查看覆盖` 后，分类筛选被设置为推荐轨道所属领域。

## 不做

- 不新增后端字段。
- 不新增独立覆盖详情页。
- 不新增复杂动画或状态机。
