# 面试题库健康诊断与检索预览

## 目标

让管理员在真实用户开启面试前，能判断题库组合是否可用、索引是否健康、追问检索是否能命中预期内容，降低运行时 fallback 和题库维护盲区。

## 背景

- 已完成面试题库导入、发布、批次记录、索引重建、运行时动态追问、在线编辑、版本历史、归档与恢复归档。
- 现有管理端可以维护题目，但缺少“题库是否足够支撑某个组合”的运营视图。
- 现有运行时会在题库检索不可用时回退规则追问，但管理员无法提前复现和定位 fallback 原因。
- `docs/ai-interview-integration-prd.md` 中已把“管理端检索预览”“面试覆盖率统计”“报告知识点分布”列为后续增强项；本任务优先处理管理端可观测与预检，不改普通用户面试主链路。

## 用户价值

- 管理员能快速发现题量不足、索引失败、待索引和组合不可开放问题。
- 管理员能用模拟 query 或回答预览追问检索结果，确认题库内容是否能被召回。
- 运营可以先修题、补题或重建索引，再开放用户侧面试组合。

## 需求

1. 后端新增管理员题库健康诊断接口，挂在 `/api/v1/admin/interview-bank` 下。
2. 健康诊断按 `domain / category / difficulty` 聚合，并区分 opening、followup、mixed 的可用数量。
3. 健康诊断需要返回每个组合的状态：`open`、`warning`、`blocked`。
4. 组合状态至少考虑：
   - `published` 题量；
   - opening 可用题量；
   - followup 可用题量；
   - `vector_status=indexed` 的追问资源数量；
   - `pending` / `failed` 索引数量；
   - `archived` 占比或数量。
5. 健康诊断需要返回不可开放或告警原因，例如：开场题不足、追问题不足、索引未就绪、索引失败。
6. 后端新增管理员检索预览接口，支持输入 `domain`、`category`、`difficulty` 和 `query` 或模拟回答文本。
7. 检索预览复用运行时题库追问检索边界，只召回 `status=published` 且 `vector_status=indexed` 的 `followup/mixed` 资源。
8. 检索预览返回召回结果摘要、fallback 原因、命中数量和检索诊断信息。
9. 检索预览不得创建面试会话，不得写入正式检索日志，不得改变题目版本或索引状态。
10. 前端题库管理页新增“健康诊断”视图，展示组合矩阵、总体健康摘要、索引异常和题量不足原因。
11. 前端题库管理页新增“检索预览”视图，管理员可选择组合并输入模拟文本查看召回结果。
12. 前端应从健康诊断视图提供跳转或筛选入口，方便定位对应题目列表或触发重建索引。
13. 接口仅允许管理员访问，非管理员返回权限错误。
14. 健康诊断 MVP 不纳入 `tags` 聚合维度；`tags` 当前仍可用于题目列表筛选或后续扩展，但不参与组合健康矩阵判断。

## 不做

- 不做自动异步索引任务队列。
- 不做普通用户面试运行时逻辑调整。
- 不做历史版本回滚。
- 不做报告知识点分布。
- 不做独立 AI Mentor 页面。
- 不把检索预览结果写入正式审计或面试报告。

## 验收标准

- 管理员可以看到题库组合健康矩阵和每个组合的不可开放原因。
- 管理员可以筛选或定位 `pending` / `failed` / 题量不足的题目。
- 管理员可以输入模拟文本执行检索预览，并看到命中结果或 fallback 原因。
- 检索预览不会创建会话、推进版本、修改索引状态或污染正式检索日志。
- 非管理员无法访问健康诊断和检索预览接口。
- 前端通过 `npm --prefix frontend run lint` 和 `npm --prefix frontend run build`。
- 后端通过 `cd backend; go test ./internal/httpapi ./internal/store`；如复用 AI 检索逻辑较多，再补跑 `go test ./...`。

## 已确认决策

- 健康诊断 MVP 只按 `domain + category + difficulty` 聚合，不纳入 `tags` 维度。
- 原因：`tags` 当前允许管理员自由填写，质量和命名还不稳定，过早进入健康矩阵会制造高基数噪声并误导运营判断。
- 后续等标签规范化成熟后，再评估增加 tag 过滤或标签健康视图。
