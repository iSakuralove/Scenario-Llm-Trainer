# 技术设计

## 验证方式

- 复用本机 Chrome 已有登录态，优先认领真实 `/interview-bank` 标签页。
- 使用 DOM/Playwright 通道读取可见文本、执行点击和填写；必要时用截图确认布局。
- 使用桌面宽度完成业务链，再切换到 390px 视口检查响应式。
- 每个写操作后重新读取详情和历史，确认前端状态与后端结果一致。

## 验证顺序

1. 确认目标标签页、URL、管理员身份和本地环境。
2. 验证运营动作列表、过滤和空状态。
3. 打开已有动作详情，检查 evidence、atom 上下文与 stale 状态。
4. 验证套用组合、打开 atom 和单 atom 重建。
5. 验证备注校验、状态更新、历史刷新与重开。
6. 切换 390px 视口，检查横向溢出、文本换行和操作可达性。
7. 如发现问题，回到代码修复并重新运行 lint/build 与浏览器复验。

## 回滚与限制

- 状态更新属于本地演示数据，可通过重开恢复为 active 状态。
- 不通过浏览器删除数据。
- 如果真实 Chrome 没有管理员登录态，停在登录/身份前置条件并说明，不伪造验证结论。
