# 面试舱真实题目选择与简历深挖启动台

## 目标

把面试舱从“聚合轨道入口”改为可搜索、可精确启动的真实题目列表，并在同一页面支持自由选题、岗位专项和简历深挖。

## 修改范围

- 面试题库原子、导入校验、版本快照和数据库字段。
- 面试启动台与会话创建 API。
- 多份简历导入、质量过滤、文件资产和简历深挖上下文。
- `/interviews`、个人档案和题库管理前端。
- 响应式样式、移动设置面板和岗位搜索。

## 核心实现

- `open_tracks` 改为一题一记录，返回 `question_id / stable_code / opening_question / question_type`，自由选题按 `question_id` 精确启动。
- 新导入开场题必须提供不超过 50 字的开场题干、四类题型之一和稳定题号；旧题迁移期使用确定性回退。
- 推荐排序把合格简历文本与目标岗位分开计分，严格先比较简历与项目经历，再比较岗位、未练习和更新时间；只重排现有题目。
- 页头只保留模式切换和开始按钮；卡片选中后右上角只显示勾选标记。
- 岗位专项增加岗位名称/技术范围搜索。
- 多份简历保存在用户档案中；PDF/DOCX 保留原资产并只读，TXT/MD/手动填写可编辑。
- 简历内容在保存和启动时复用同一质量规则，失败不覆盖旧数据。
- 桌面简历工作区使用 `260px + 1fr`，移动端使用文件选择菜单并在阅读区标题栏提供“加入本场”；正文在固定阅读区内部滚动。
- 移动端常用设置收敛为摘要和“调整”面板；320px 与浏览器缩放下无页面级横向滚动。
- 前后端版本错配时显示五道可启动基础题，不把旧聚合响应渲染为空列表。

## 影响范围

- 旧 Docker API 镜像返回聚合轨道时，新前端会进入兼容回退；部署应原位更新 API 镜像以恢复全部真实单题。
- 旧题库内容未提供开场题干时仍可展示，但题干质量取决于迁移回退；后续导入必须满足新标准。
- 简历深挖会话保存候选人上下文快照，后续编辑档案不会改写历史会话。

## 验证方式

- `go test ./... -count=1`
- `TestSortInterviewLaunchpadTracksPrioritizesResumeBeforeTargetRole` 与 `TestSortInterviewLaunchpadTracksFallsBackToTargetRole`
- `pnpm --dir frontend run lint`
- `pnpm --dir frontend run build`
- 真实浏览器验证 1920、1440、1024、768、375、320 宽度，无页面级横向溢出。
- 验证题目选择、开始按钮、稳定题号搜索、岗位搜索、移动设置面板和无简历禁用状态。
- 原位替换 `teaching-mvp-api-1` 后，容器二进制哈希与本地构建一致；真实页面恢复 476 道单题，第一页显示 18 道。

## 已知限制

- 旧版 `.doc` 不支持，只支持 `.docx`。
- 现存旧题如果本身重复或开场题干同质化，需要后续按标准 JSON 清洗内容；本功能不自动改写题库正文。
- 当前管理员账号没有简历数据，真实浏览器只验证了无简历禁用状态；多格式简历读写由后端回归测试覆盖。
