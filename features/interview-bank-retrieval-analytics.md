# 面试题库真实命中运营看板

## 目标

让管理员看到真实面试追问检索中的题库命中、规则回退和低效资源，补齐导入、编辑、索引重建之后的运营观察闭环。

## 修改范围

- 后端补齐 `InterviewRetrievalLog` 的运行时写入、Store 查询和聚合统计。
- 管理员 API 新增真实检索日志列表和运营分析接口。
- 前端面试题库管理页新增“真实检索运营”面板。
- 同步更新 schema/migration 索引、架构文档和 Trellis Store/schema 契约。

## 核心实现

- 真实追问检索结束后写入日志；命中记录轻量 atom 快照，回退记录 `fallback_used` 和错误/原因摘要。
- `query_text` 先走脱敏，再截断到 500 字；写日志失败不阻断面试流程。
- Store 提供保存日志、按条件读取日志、聚合真实检索运营摘要的最小接口，MemoryStore 与 PostgresStore 保持同一语义。
- 管理端看板展示真实检索次数、命中率、回退率、热门命中原子、低/未命中原子、回退组合排行和最近日志。
- 回退组合可一键套用到现有题库筛选和检索预览表单，便于继续诊断或补题。

## 影响范围

- 运行时面试提交流程新增一次轻量日志写入，但失败不会影响用户答题和报告生成。
- 管理员端新增只读运营接口；普通用户和非管理员不能访问。
- 不改变用户侧报告接口，不新增 LLM 调用，不自动修题、归档或重建索引。

## 验证方式

- `cd backend; go test ./internal/httpapi ./internal/store`
- `npm --prefix frontend run lint`
- `npm --prefix frontend run build`
- `cd backend; go test ./...`

## 已知限制

- 分析窗口按接口 `limit` 限制聚合，首期不做长周期趋势、自动归因或自动修题。
- 低/未命中原子只作为运营线索，不代表题目质量判断。
- 检索日志只保留脱敏截断 query 和轻量元数据，不支持查看完整用户回答或背景原文。
