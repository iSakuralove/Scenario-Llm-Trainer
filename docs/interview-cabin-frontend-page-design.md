## 1. 文档目的

本文档用于把已确认的 AI-Interview 能力迁移、题库治理和面试舱重构决策落到前端页面设计中。

本轮只产出前端页面设计，不继续改动前端源码。

## 2. 设计约束

### 2.1 已确认技术决策

- 采用能力迁移，不直接并入外部 `AI-Interview` 运行时。
- 前端继续使用当前 React 工作台，不新增 Vue / Element Plus 并行入口。
- 后端继续使用 Go，数据真相继续落在 PostgreSQL。
- 面试题库首期引入 `InterviewKnowledgeAtom` 作为可发布、可检索、可审计的题库原子。
- 现有 `InterviewQuestion` 在首期只作为兜底数据源，而不是承载全部题库治理职责。
- 用户侧面试舱只能消费已发布、可命中开放组合的题库内容。
- 管理端负责导入、校验、预览、发布、归档、恢复归档、重建索引等治理动作。

### 2.2 首期开放范围

首期用户侧只展示后端已确认可用的组合：

- `java + L2/L3`
- `database + L2/L3`
- `cache + L2/L3`
- `ai_llm + L2/L3`

前端不得自行补齐未开放组合，也不得把未开放组合渲染为灰态入口。

### 2.3 设计系统约束

前端页面应继续遵循当前项目的命令屏式深色产品系统：

- 背景使用深色渐变与细网格，不做温暖浅底卡片页。
- 卡片使用清晰边界和轻量层级，减少装饰性光效。
- 重要操作使用青绿色信号色，风险与异常使用少量玫红。
- 中文技术长文本优先保证可读性，避免大段正文居中。
- 页面密度应服务“选择训练”和“理解题库状态”，而不是只做营销式启动页。

## 3. 页面定位

新版面试舱不是“静态训练卡片集合”，而是题库驱动的面试启动台。

它需要同时回答用户的四个问题：

1. 我现在可以练什么？
2. 为什么系统推荐我练这个？
3. 这个训练覆盖哪些能力域、主题和题型？
4. 我之前练得怎么样，下一步该补哪里？

因此，用户侧页面只展示可训练入口和必要解释，不展示后台导入、版本、审计等管理噪声。

## 4. 信息架构

### 4.1 页面一级结构

建议新版面试舱按以下结构组织：

1. 顶部状态区
   - 当前可用题库范围
   - 已发布题库数量
   - 索引增强状态
   - 最近一次训练入口
2. 推荐训练区
   - 基于历史表现、岗位目标或当前开放组合推荐 1-4 个训练入口
   - 每个入口对应一个 `Track`，不是题库分类本身
3. 可启动组合区
   - 只展示后端返回的开放组合卡片
   - 不展示未开放组合，也不展示“敬请期待”占位
   - 提供 `category / difficulty / question_role / tags` 的轻量筛选
4. 能力覆盖区
   - 展示领域覆盖、难度覆盖、题型覆盖
   - 让用户知道当前题库偏向，而不是误以为所有方向都已成熟
5. 历史表现区
   - 展示最近面试、五维评分、待补能力点
   - 支持继续未完成面试或查看报告
6. 空状态 / 降级状态区
   - 无开放组合、题库索引失败、接口异常时提供明确解释和回退路径

### 4.2 用户侧不展示的内容

以下内容属于管理端，不应直接进入用户侧主页面：

- 导入批次明细
- 版本历史表
- 归档原因全文
- `source_ref` 原始来源
- `batch_id`
- 题目稳定 `id`
- 管理员编辑备注
- 审计字段

用户侧可以展示简化后的状态，例如“题库已更新”“追问增强准备中”“该方向暂未开放”。

## 5. 分类模型在页面中的表达

### 5.1 Domain：稳定能力域

`Domain` 是页面导航的主轴，建议作为题库探索区的第一层。

推荐展示方式：

- 能力域名称
- 可训练组合数
- 已发布题目数
- 覆盖难度
- 最近更新状态
- 推荐入口按钮

注意：`Domain` 不等于外部导入包中的自由文本，也不应允许前端临时新增。

### 5.2 Category：受控一级分组

`category` 用于题库统计和筛选，首期应保持少量受控枚举。

前端展示时建议：

- 作为筛选 chip 出现
- 不作为主导航树
- 不允许用户看到无法解释的内部枚举名
- 显示中文名和简短说明

### 5.3 Tags：轻量补充维度

`tags` 用于描述更细粒度技术点，例如 `redis`、`mysql`、`jvm`、`rag`。

前端展示时建议：

- 只展示高频或与当前结果相关的标签
- 标签数量过多时折叠
- 筛选后必须保留“清空筛选”入口
- 不把标签做成新的层级目录

### 5.4 Track：用户训练入口

`Track` 是面向用户的一次训练组合，例如“数据库 L3 情景排障训练”。

它可以由多个条件组合生成：

- `domain`
- `category`
- `difficulty`
- `question_role`
- `tags`
- 用户历史表现
- 当前开放组合配置

前端必须避免把 Track 当作题库分类维护。Track 只负责“怎么开始一次训练”。

## 6. 核心页面模块设计

### 6.1 顶部状态区

目标：快速说明当前面试舱是否可用，以及题库增强能力是否生效。

建议字段：

- `publishedAtomCount`：已发布知识原子数量
- `openTrackCount`：当前可启动训练组合数量
- `indexedAtomCount`：已完成索引数量
- `vectorStatusSummary`：索引状态摘要
- `lastSession`：最近一次面试状态

建议文案示例：

- “当前开放 4 个训练方向、8 个可启动入口，覆盖 Java、数据库、缓存和 AI / LLM。”
- “追问增强已覆盖 126 条题库原子；索引失败不影响开场题训练。”
- “你上次在数据库 L3 训练中表达结构得分偏低，建议继续练习排查步骤组织。”

### 6.2 推荐训练区

目标：减少用户选择成本。

推荐卡片应包含：

- 训练名称
- 适合对象
- 覆盖能力域
- 难度
- 题型
- 预计耗时
- 推荐原因
- 题库状态
- 主按钮：开始训练
- 次按钮：查看覆盖

推荐原因不应是泛文案，应来自可解释信号：

- 最近低分维度
- 新发布题库
- 用户岗位目标
- 常用训练轨道
- 未完成会话

### 6.3 可启动组合区

目标：让用户按能力方向主动找训练。

建议布局：

- 左侧或顶部为 Domain 切换
- 主区展示开放组合卡片
- 顶部提供难度、题型、标签筛选
- 无结果时解释“没有开放组合”的原因

组合卡片建议字段：

- `trackTitle`
- `domainLabel`
- `difficultyLabel`
- `questionRoleLabel`
- `publishedCount`
- `indexedCount`
- `coverageTags`
- `availabilityState`
- `unavailableReason`

可用状态建议：

- `available`：可开始训练
- `indexing`：可开场，追问增强准备中
- `insufficient_questions`：题量不足，暂不可训练
- `no_opening_question`：缺少开场题
- `archived_only`：当前只有归档题，不进入主链路

### 6.4 能力覆盖区

目标：让用户和评委理解题库不是黑盒。

建议以轻量统计卡呈现：

- 能力域覆盖
- 难度分布
- 题目角色分布：opening / followup / mixed
- 索引状态分布：pending / indexed / failed

用户侧只需要摘要，不需要管理表格。

### 6.5 历史表现区

目标：把训练入口和反馈闭环连接起来。

建议展示：

- 最近 3-5 场面试
- 五维评分摘要
- 最低维度和建议训练方向
- 未完成会话继续入口
- 报告查看入口

历史会话必须读取当时的 `question_snapshot` 与相关题库快照，不应被题目新版本反向污染。

## 7. 页面状态设计

### 7.1 加载状态

加载时应按真实结构显示：

- 顶部状态骨架
- 推荐卡片骨架
- 题库探索筛选骨架
- 历史记录骨架

避免整页 spinner，因为用户不知道是题库、历史还是推荐在加载。

### 7.2 空状态

常见空状态：

1. 没有已发布题库
   - 文案：当前还没有可用于面试的已发布题库。
   - 操作：提示管理员先完成导入、预览和发布。
2. 有已发布题库但没有开放组合
   - 文案：题库已发布，但暂未满足任何训练组合的启动条件。
   - 解释：可能缺少 opening 题、难度不匹配或组合未开放。
3. 当前筛选无结果
   - 文案：没有符合筛选条件的训练组合。
   - 操作：清空筛选。
4. 历史记录为空
   - 文案：完成一次训练后，这里会展示评分趋势和复盘报告。

### 7.3 错误与降级状态

错误状态要区分：

- 题库接口失败
- 历史记录接口失败
- 推荐接口失败
- 索引状态异常

索引失败时页面不应误报“不能训练”。根据已确认技术决策：

- 开场题仍可从已发布记录中按普通条件筛选。
- 追问检索失败时回退到规则化追问链路。
- 用户侧可以提示“追问增强降级中”，但仍允许完成面试。

## 8. 前端接口契约建议

### 8.1 页面聚合接口

建议提供面试舱启动台聚合接口，避免前端拼多个内部表。

接口：`GET /api/interviews/launchpad`

返回建议：

- `summary`
- `recommendedTracks`
- `domains`
- `openTracks`
- `coverage`
- `lastSessions`
- `fallbackMode`

### 8.2 开放组合接口

接口：`GET /api/interviews/open-tracks`

用途：

- 获取用户可见训练入口
- 展示不可用组合的解释
- 支撑筛选与 Domain 导航

### 8.3 历史表现接口

接口：`GET /api/interviews/sessions/recent`

用途：

- 最近训练记录
- 未完成会话
- 评分摘要
- 推荐下一步训练方向

### 8.4 用户侧不应直接调用的接口

用户侧面试舱页面不应直接调用：

- 题库导入接口
- 题库发布接口
- 单题归档接口
- 版本历史明细接口
- 重建索引接口

这些都属于管理端页面。

## 9. 与管理端的边界

### 9.1 用户侧面试舱

用户侧负责：

- 发现可训练入口
- 理解训练覆盖
- 开始或继续面试
- 查看历史表现
- 接收必要降级提示

### 9.2 题库管理端

管理端负责：

- 导入题库
- 校验字段完整性
- 试运行 / 预览
- 发布
- 在线编辑已发布题
- 归档
- 恢复归档
- 重建索引
- 查看版本历史和审计信息

两者边界必须清晰，否则用户侧页面会变成半个后台，影响训练体验。

## 10. 首期前端落地步骤

### Phase 1：文案与信息架构收敛

- 保留现有页面路由和启动训练流程。
- 将页面文案从“静态卡片选择”调整为“题库驱动训练”。
- 增加题库状态摘要、开放组合解释和空状态文案。
- 不直接扩展复杂管理动作。

### Phase 2：接口驱动替换静态配置

- 新增 launchpad 聚合接口调用。
- 保留 `launchpadConfig.ts` 作为接口失败时的前端兜底。
- 将 Track 数据结构从硬编码卡片迁移为后端开放组合返回。
- 前端只渲染后端认为可见的组合。

### Phase 3：分类筛选与覆盖解释

- 增加 Domain 导航。
- 增加 category / difficulty / question_role / tags 筛选。
- 为不可用组合展示原因。
- 增加覆盖统计卡片。

### Phase 4：历史表现驱动推荐

- 接入最近会话与评分摘要。
- 根据最低维度、未完成会话、新发布题库生成推荐训练。
- 推荐原因必须可解释。

### Phase 5：管理端联动

- 用户侧只展示题库可用状态。
- 管理端新增题库列表、导入预览、编辑、归档、恢复、版本历史和重建索引。
- 用户侧与管理端共享状态枚举和展示标签，但不共享管理动作。

## 11. 前端组件拆分建议

建议拆分为以下组件，避免 `InterviewsPage` 继续膨胀：

- `InterviewLaunchpadSummary`
- `RecommendedTrackCard`
- `InterviewDomainNav`
- `OpenTrackGrid`
- `TrackAvailabilityBadge`
- `InterviewCoveragePanel`
- `RecentInterviewList`
- `InterviewLaunchpadEmptyState`
- `InterviewLaunchpadErrorState`

组件命名以用户任务为中心，不以数据库表名为中心。

## 12. 字段映射建议

| 后端字段 | 用户侧展示 | 说明 |
| --- | --- | --- |
| `domain` | 能力域 | 页面主导航 |
| `category` | 分类筛选 | 受控枚举，少量展示 |
| `tags` | 技术标签 | 可折叠展示 |
| `difficulty` | 难度 | 显示首期开放组合对应级别及语义标签 |
| `question_role` | 题目角色 | opening / followup / mixed 的用户化说明 |
| `status` | 可用状态 | 用户侧不直接展示 draft |
| `vector_status` | 追问增强状态 | 只显示摘要，不阻断开场训练 |
| `current_version` | 不展示 | 管理端使用 |
| `source_ref` | 不展示 | 管理端与审计使用 |
| `batch_id` | 不展示 | 管理端使用 |

## 13. 页面验收标准

首期页面设计完成后，应满足：

- 用户能在 5 秒内理解当前可以练什么。
- 用户能看到训练入口背后的能力域、难度、题型和题库状态。
- 没有题库、没有开放组合、索引失败、接口异常时都有明确解释。
- Track 不再被当作题库分类本身。
- 前端不再依赖不断膨胀的静态卡片配置作为唯一数据源。
- 历史表现能反向驱动下一次训练推荐。
- 用户侧不暴露导入、审计、版本、归档等管理噪声。

## 14. 暂不纳入本页面的事项

- 题库导入后台完整交互稿。
- 版本历史详情页。
- 在线编辑题目的表单细节。
- 批次导入失败修复工具。
- 多人审批流。
- 复杂运营数据看板。

这些内容应在题库管理端文档中单独展开。
