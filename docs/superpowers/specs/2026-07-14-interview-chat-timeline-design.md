# 面试舱聊天式时间线设计

## 目标

将当前“题目卡 + 整屏编辑器”的面试会话改造成聊天式面试时间线：面试官与用户使用左右气泡和头像区分，历史轮次可回看，右侧提供轮次与消息锚点跳转；保留 Markdown 能力，但默认采用轻量聊天输入。

## 已确认选择

- 输入模式：C。默认普通文本输入，点击“展开编辑”后进入 Markdown/代码/Mermaid 编辑器。
- 页面方案：2。中间聊天流 + 右侧面试导航；题目上下文保留在聊天流顶部。
- 数据策略：复用现有会话详情中的题目、追问、`submissions`、`evaluations` 等字段，不新增数据库表。

## 页面结构

### 桌面端

1. 顶部题目摘要：领域、难度、轮次、标题和问题描述。
2. 中间聊天流：面试官消息左侧、用户回答右侧；每轮有分隔线；当前待回答区域位于底部。
3. 右侧固定导航：轮次节点和消息节点，点击后滚动并更新 URL hash；当前可视消息自动高亮。

### 移动端

- 聊天流占满宽度。
- 右侧导航折叠为顶部可展开抽屉。
- 抽屉不得遮挡输入区，390px 宽度下无页面级横向溢出。

## 交互与状态

- AI 气泡使用 AI 头像，用户气泡使用用户首字母或头像；时间、轮次和来源以文字同时表达，不只依赖颜色。
- 默认输入为普通文本；展开编辑后复用现有 Markdown 工具栏、预览、全屏和导入能力。
- 提交后将用户回答追加到时间线并清空输入区；追问生成期间显示骨架屏，失败时在时间线内提供重试。
- 导航节点分为已完成、当前、未解锁三态；未解锁节点不可跳转。
- 支持 Tab/Enter 键盘操作，Esc 关闭编辑抽屉；尊重 `prefers-reduced-motion`。
- 锚点使用 `scrollIntoView`，hash 形如 `#round-2-followup`，刷新后尝试恢复定位。

## 数据与兼容性

- 有历史字段时按时间线展示题目、回答、追问和评分节点。
- 旧会话缺少历史消息时只展示可确认的题目和当前轮次，并显示“历史消息暂不可用”，不伪造内容。
- 不改变现有提交回答、语音转写、追问和报告 API 契约。

## 验收标准

- 1920×1080 下聊天流、输入区和右侧导航层级清晰。
- 390px 下气泡、头像、输入区和导航抽屉可操作且无横向溢出。
- 已有回答可回看；刷新后时间线和 hash 定位不丢失。
- 提交后聊天流、导航状态和输入区同步更新。
- Markdown 编辑能力可展开使用，不默认占据整屏。
- 旧会话数据不足时显示明确空状态。
